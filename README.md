# Анализ и моделирование данных предметной области

## 1. Описание предметной области

Предметная область: Медицинская клиника

Медицинская клиника оказывает медицинские услуги.

Основные процессы:
- ведение информации о пациентах и врачах;
- запись на приём;
- проведение приёмов;
- хранение информации об оказанных услугах.

Пользователи системы:
- пациенты;
- врачи и медицинский персонал.

Основные задачи информационной системы:
- хранение информации о пациентах;
- хранение информации о назначениях для пациентов 
- хранение информации о врачах и их расписании;
- учет проведенных приёмов;
- учет услиуг оказанных во время приёма.

## 2. Объекты данных

В предметной области выделены следующие основные объекты данных.

### Пациент

Клиент, которому нужны медицинские услуги.

Необходимо хранить:
- ФИО;
- индефикатор пациента;
- дата рождения;
- номер телефона;
- пол.

### Врач

Спефиалист, оказывающий медицинские услуги.

Необходимо хранить:
- ФИО;
- индефикатор врача;
- специальность;
- номер телефона;
- график работы.

### Приём

Информация о проведённом приёме пациента.

Необходимо хранить:
- индефикатор приёма;
- индефикатор пациента;
- индефикатор врача;
- дата и время приёма;
- описание жалоб;
- описание о выполненных услуг;
- стоимость приёма.

### Услуга

Медицинкая услуга, которая может быть оказана в рамках приёма.

Необходимо хранить:
- индефикатор услуги;
- названи;
- описание;
- стоимость.

### Медицинское заключение

Документ, оформляемый по результатам приёма.\

Необходимо хранить:
- индефикатор заключения;
- индефикатор приёма;
- номер заключения;
- дата оформления;
- дигноз и назначения.

## 5. Связи между объектами

Между объектами предметной области были определены следующие связи.

### Пациент - 1:N

Тип связи: один ко многим (1:N).

Один паицент может иметь несколько приёмов.

### Врач - Приём

Тип связи: один ко многим (1:N).

Один врач может иметь несколько приёмов.

### Приём - Медицинское заключение

Тип связи: один к одному (1:1).

По результатам одного приёма оформляется одно медицинское заключение.

### Приём - Услуга 

Тип связи: многие ко многим (M:N).

В рамках одного приёма может быть оказано несколько услуг. Одна и та же услуга может быть оказана в рамках разных приёмов.

## 6. Концептуальная модель данных


На схеме отражены следующие связи:

- Пациент 1:N 1:N;
- Врач 1:N Приём;
- Приём 1:1 Медицинское заключение
- Приём M:N Услуга

## 7. Оценка качества исходных данных

После построения концептуальной модели была выполнена оценка полноты и качества данных.

### Достаточно ли объектов выделено?

Да. Выделенные объекты описывают основные данные, необходимые для учета пациентов, врачей, приёмов, услуг и медицинских заключений.

### Отсутствуют ли важные сущности?

Для рассматриваемой модели основных сущностей достаточно. При дальнейшем развитии системы могут быть расписание врачей , медикаменты, платежи и другие объекты.

### Все ли необходимые атрибуты определены?

Для построения концептуальной модели определены основные атрибуты каждого объекта. При реализации реальной информационной системы набор атрибутов может быть расширен.

### Имеются ли дублирующиеся данные?

Явного дублирования данных в модели нет. Информация о пациентах, врачах, приймах, услунах и медицинских заключениях хранится в отдельных объектах и связывается между собой.

### Достаточно ли информации для дальнейшего проектирования информационной системы?

Да. Выделены основные объекты, их атрибуты и связи. Полученная модель может использоваться как основа для дальнейшего проектирования базы данных.
